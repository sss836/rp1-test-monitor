## 5台模拟全链路

实际创建5个模拟采集进程、5个relay及中央服务，运行26.50秒。原始结果见 process-monitor-e2e.json（本机历史材料，不随源码发布）。

- 进程观测到达上位机与中央，Qt能打开并正常退出。
- 关闭Qt后后台上传继续；中央短时中断时电脑队列保留数据，恢复后补传。
- 模拟网线中断时机器人继续缓存；恢复后源端序号无缺口。
- 失联设备的进程状态变未知、资源值为空，不影响另外4台。
- 测试数据库记录118个窗口，平均JSON大小36,743字节。按本次包含24关节和2个模拟进程的完整摘要估算，单台30天约88.7 GiB，10台约887 GiB，仅算JSON；表、索引、WAL、备份和真实配置另计。这不是已实现的精简关键曲线容量。

## 新增轮询的本机开销

脚本创建10个命名测试子进程，读取本机可见的686个PID，轮询200轮并验证退出/重启及CPU重新预热；只结束本脚本创建的子进程。结果见 process-monitor-cost.json（本机历史材料，不随源码发布）。

| 测项 | 本机测量 |
|---|---|
| 每轮wall耗时中位数 / P95 | 4.190 / 6.879 ms |
| 每轮新增CPU时间 | 4.592 ms |
| 按2秒周期折算的单核CPU比例 | 0.2296% |
| 内存追踪保留分配增长 / 峰值 | 15,791 / 76,188 bytes |
| 保存的上一轮计数 / 实例身份 / 指标项 | 10 / 10 / 50 |

这些是当前Linux电脑上的短时测试，内存追踪仅覆盖Python分配，不能替代完整采集服务RSS测量，也不能证明RP1长期运行开销或控制实时性。热路径使用普通文件读取，避免为每个临时PID创建并驻留路径片段；不采集进程内存映射或命令行。
