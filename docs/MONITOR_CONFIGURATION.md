# 逐机器人机型、温度策略与诊断联动

2026-10-23 已完成软件和模拟验证。当前入口为 [管理员工作台](http://127.0.0.1:18940/admin) 与 [中央大屏](http://127.0.0.1:18940/)。支持 24／28 自由度；真实关节顺序、总线编号、物理部位及温度限值仍待实机资料确认。

## 管理配置

登录管理员工作台，选择机器人，进入「机型与温度策略」。填写硬件版本、自由度、显示色阶，以及每个规范索引的关节名称、显示名、部位、总线和电机编号。总线与编号需成对填写；未知字段可以留空，不会生成实机映射或安全限值。

电机与 MOS 超温限值逐关节独立配置，判据为严格大于限值。色阶范围仅影响浅粉至深红的显示，不改变报警阈值。不同机器人可使用不同限值；电池和主机温度的全局规则继续保留。

填写保存原因后点击「保存为新版本」。历史版本保留修改人、时间和原因，操作记录同时追加审计。页面读取的版本若已被别人修改，保存会提示冲突并保留当前输入，须重新读取后核对，不会覆盖别人的新版本。新建机器人可选择 24 或 28 自由度，机器人登记与初始配置在同一事务完成。

24 改为 28 时新增四个待确认关节；28 改为 24 时页面要求确认移除当前配置末四项，旧版本和历史观测仍保留。28 自由度模拟示例的额外四关节未映射到示意图，可在列表中查看温度。

## 网页与上位机使用同一配置

中央网页从数据库读取所选机器人的最新配置。上位机后台 relay 使用已有设备凭据，每约 5 秒只读查询自己绑定机器人的非敏感配置，并附加到现场预览；Qt 使用收到的中央版本，界面显示版本号。中央地址和凭据不会下发到机器人。

已有中央版本优先于本机 JSON；无中央版本时保留原来的本机文件方式。同步失败会提示错误，relay 保留最后一次有效配置，不把它冒充为最新版本；未同步时使用本机文件或未配置状态。配置属于显示和监测层，不写回源端帧、原始摘要、哈希或本机配置文件。

已有中央配置的模拟上位机可直接启动，无需再传映射和温度 JSON：

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python -m rp1_monitor desktop \
  --url http://127.0.0.1:18962
```

`18961` 对应 24 自由度一号模拟机，`18962` 对应 28 自由度二号模拟机。中央服务与 relay 须已运行。非匿名环境在诊断设置填写中央只读凭据；此凭据与 relay 的设备上传凭据分开。

## 从关节到曲线与诊断

网页点击整机图部位，会打开该部位当前最热关节；也可以直接点击逐关节列表中的名称。Qt 点击图上部位，或双击电机表行／按 Enter，打开温度详情。无部位映射的关节仍可通过列表查看。

详情展示当前电机与 MOS 读数、配置限值、原始摘要历史和该关节最近 20 条温度状态变化记录。可选择最近 10 分钟、1 小时或 24 小时。缺失窗口保留断点，不填零；网页同时显示适用指标的窗口极值范围，Qt 显示两项摘要最后值曲线。

告警的条件起点、持续条件确认后的触发时间、恢复确认时间与观测丢失事件分别保留。告警开启历时不代表已证实连续超温时长，失联不自动记作恢复。历史事件保留当时策略证据，当前限值不会重写旧事件。配置换版后，旧评估标为待重新评估，直到新策略下的观测确认。

点击「带入诊断对话」会预填当前关节、时间范围和电机／MOS 两项指标，由用户点击发送。此步骤本身不调用模型；未启用模型时使用本地规则与查询证据，启用模型仍遵循已有模型设置和证据发送选择。切换机器人会隔离旧查询结果与对话上下文。

## 数据库与验证

新增显式迁移 [005_robot_configuration.review.sql](../deploy/postgres/005_robot_configuration.review.sql)，追加配置版本表后当前 schema 共 **14 张表**。配置通过受控函数追加，管理员无直接修改配置版本表的权限；普通 API、只读角色及设备配置查询均不能借此写配置。版本校验与审计在同一事务内完成。应用启动不自动执行 DDL。

已有本任务专用模拟 Docker 环境已先备份再应用 005；未删除原始数据、未重建数据库。检查／升级工具仅允许匹配的专用 compose 环境，并拒绝包含非模拟设备的数据库：

```bash
# 默认只检查，不修改
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python scripts/upgrade_central_configuration.py \
  --runtime runtime/postgres-central
# 显式升级会先创建私有 pg_dump，再执行005
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python scripts/upgrade_central_configuration.py \
  --runtime runtime/postgres-central --apply
```
