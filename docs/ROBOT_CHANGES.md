## 读取位置与行为

- 关节、策略目标、IMU：订阅已有 ROS 消息，不发布控制消息。
- 电池：读取现有 `bms.service` 新日志，不另开 CAN 总线、不重新初始化 BMS。
- 主机：读取 `/proc/stat`、`/proc/meminfo`、`/proc/uptime`、`/sys/class/thermal/`。
- 指定进程：读取 `/proc`，不启停或重启被观察的进程。
- 每核 CPU：在现有约一秒的主机采样中读取同一份 `/proc/stat`，通过相邻两次计数计算单核使用率。只读 `/sys/devices/system/cpu/cpu*/cpu_capacity` 获取大小核分组；不能确认时显示未识别。

关节数据先由机器人原有驱动/运控读取，再由机器人上的本项目采集节点订阅`/joint_states`（位置、速度、上报effort）和`/action`（策略目标），生成摘要后经SSH与relay交给上位机。本机Qt和网页读取这些摘要，不直接通过网线订阅机器人的ROS图。电机温度、MOS温度和故障另需已有驱动缓存通过诊断话题提供，并经真实关节名、总线、电机ID和协议映射校验；仅运行推理不代表这些字段已接通。主机热区不能代替电机温度。

这些操作不要求关节使能。没有反馈不自动等同于未使能或故障。
