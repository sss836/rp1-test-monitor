# 功能如何实现，以及为什么这样选

> 版本说明：本文保留对应旧版设计/验证范围。v0.4.0已改为机器人经网线上位机relay上传，当前启动参数、凭据位置和退出行为以 [WIRED_RELAY.md](WIRED_RELAY.md) 为准；旧测试记录不构成新拓扑验收。

## 需求与范围

用户当前主要需要实时整机监控，并将数据持续汇总到数据库与大屏。现场使用独立电脑App；已有手柄继续控制机器人。故本版以只读监测为闭环，不把早期“Agent工作台”设想全部纳入。

确认的基础条件：RP1已有实机、Linux开放、ROS2、有现成日志/录包工具、团队熟悉ROS。尚未确认：实机ROS发行版与Python ABI、最终数据保留精度/时长、物理关节映射、并发实机数、生产平台部署参数。

## 数据入口

v0.2.0核心健康来源、字段语义和文件级说明见 [HEALTH_IMPLEMENTATION.md](HEALTH_IMPLEMENTATION.md)；生产者固定版本依据见 [HEALTH_SOURCES.md](HEALTH_SOURCES.md)。ROS三话题只承担运动遥测，不代表整机健康已覆盖。

`RosSource`只创建三个订阅，没有publisher、service client或运动控制调用。

| Topic | 消息 | 取值 | 注意 |
|---|---|---|---|
| `/joint_states` | sensor_msgs/JointState | position、velocity、effort | rad、rad/s、按当前协议理解的N·m，实机核对 |
| `/action` | sensor_msgs/JointState | position | 原始策略目标，通常还未经过最终转换/滤波 |
| `/imu` | sensor_msgs/Imu | orientation、angular_velocity | 不显示当前源码未提供的线加速度 |

QoS默认 best_effort、volatile、keep_last(50)。这是低影响的观察订阅；它不保证记录控制循环的每个样本。订阅端摘要只能保留实际收到的数据。真实Topic频率、DDS丢包和CPU占用需实机测量。

首次有效反馈关节名按自然顺序形成规范索引，避免跨进程重启时数组重排改变指标含义。中央登记保存首次规范名单，后续名单改变会拒绝混入同一机器人的历史并告警。之后收到相同名字的重排时按名字还原顺序；名单变化、无名字或超出64个关节时暂停反馈更新并标注异常。目标按同名对齐，或按仓库中的 `action_N → joint_N` 命名协议对应。无法确认时隐藏目标值。消息名对应关系不等于物理左右腿/电机映射已经核对。

IMU使用协方差首项为-1的不可用约定；全零四元数不作为有效姿态。四元数保留原始最后值，不按分量做平均或极值。

## 三条不同速率的链路

1. **源数据观察**：每条接收到的消息进入 `Accumulator`，更新当前值、窗口样本数及适用指标的最小/最大值。
2. **现场预览**：采集服务通过WebSocket约10Hz发送快照。Qt保留约60秒、每指标最多600点；一次最多选择12条、按单位分组。预览不是完整原始曲线，可能略过两个预览点之间的尖峰。
3. **中央留存**：约每秒生成不可变摘要，写入本地SQLite队列，再由独立上传线程发到中央API。摘要极值来自源消息观察，不来自10Hz预览，能保留收到的短时峰值。

关节位置、速度、力矩、策略目标和角速度存 last/min/max/count/age。四元数存 last/count/age。调度迟到时记录实际窗口长度，不伪称固定1秒；极长窗口属于异常运行，尚未对系统休眠恢复做实机验收。

## 时钟和缺失

每个采集进程用UTC锚点加单调时钟构造接收时间，避免墙钟回拨破坏窗口。保留每Topic最新发布头时间，但不声称它是传感器硬件采样时间，也不保存每一个原始头时间。

无新样本的指标 last 为 null、count为0。运动预览超过1秒未更新变为null，低频健康观测使用5秒时效。健康当前值另保留last-observed及年龄，不修改无样本窗口事实；HTTP快照到达时间不能充当硬件字段采样时间。网页按单指标年龄隐藏过期值。曲线遇到缺失窗口或缺口会断线。

大屏区分采集端在线、传感数据新鲜和时钟待核对。服务端拒绝将与服务器偏差超过5秒、或墙钟异常的live记录更新为latest，但仍接收为历史并返回提示。`HOST_ANCHORED`只说明时间构造方式，并不是时钟同步认证。上线前仍要校时。

## 缓存、补传与数据库

- 队列使用SQLite WAL，未取得明确receipt前不删除。进程重启会产生新的stream UUID，序号重新从1开始，旧队列继续补传。
- 上传线程和摘要线程分开。网络重试最多退避30秒，实时预览不依赖网络上传成功。
- 先上传当前实例的最新窗口；有积压时live与backfill请求交替，避免持续到来的新窗口饿死旧队列。backfill只入历史，不覆盖大屏当前状态。历史批次被409/422拒绝时保留原记录、显示独立历史异常，30秒后重试；当前live可继续，成功的实时请求不会掩盖未解决的历史异常。
- 唯一键为 `(robot_id, stream_id, sequence)`。相同内容重试只确认一次；相同身份不同内容返回409并回滚批次。
- PostgreSQL事务内锁定机器人登记行，串行处理该机器人的并发写入。锁内再次确认设备仍启用、令牌未被轮换。SQLite测试另加进程内锁。
- latest只接受新live记录，并检查流、序号及采集时间。旧流延迟到达不应把当前状态倒退。
- 历史查询限制31天、10～4000返回点；SQL按时间桶降采样，保留适用指标极值，并报告缺失。

队列默认1GiB是**待传JSON有效载荷预算**，不是整个SQLite文件的物理硬上限。SQLite页、WAL和日志另占空间。队列超预算会丢最旧摘要并累计可见丢失计数，近期丢失范围日志最多128条；不会静默丢失。默认磁盘剩余不足256MiB时停止摘要落盘并在App报错，恢复空间后需重启采集服务。它不删除其他文件，不替代磁盘容量规划。预算/保留值可以用agent命令参数调整。

中央仅有三张monitor表：登记、latest、windows。连续监控不要求虚构测试计划/执行ID，也不修改正式测试或MTBF数据。30天是容量估算条件，没有自动删除任务。每秒24关节数据的容量在验证记录中给出实际测量，不预先假定小到可忽略。

## 现场App和大屏

App使用PySide6/Qt，是独立窗口，默认整机健康页，第二页为关节与IMU；pyqtgraph负责连续曲线。WebSocket放在QThread，避免网络等待卡住Qt主线程。断开重连不调用机器人服务。可由系统OpenSSH建立本地转发，使用已确认的host key和密钥/ssh-agent；不保存SSH密码。

网页采用原生JS、CSS和SVG。页面包含设备列表、健康卡与来源说明、状态卡、摘要曲线、关节表，单独引入React构建项目收益不足。资产本地提供，不依赖外部CDN；读取凭据仅存页面内存，刷新后重新输入。部署到已有平台时可复用同源登录Cookie。

实时状态轮询1Hz，10分钟历史曲线约2秒刷新，较长范围降低刷新频率。后台页暂停轮询，单次请求5秒超时。设备切换时清除旧曲线，并用请求版本避免旧响应覆盖新设备。

## 认证与已有平台接入

每台机器使用独立写入令牌，只能写登记的robot_id和来源。服务器存SHA-256摘要；可撤销/轮换，历史保留。只读凭据与写入凭据不同。机器人向中央发送令牌必须HTTPS；HTTP只用于回环演示，代码不提供“跳过证书验证”。

agent监听127.0.0.1，现场通过SSH隧道读。它没有公网管理接口。当前没有多级租户权限、在线设备注册UI或完整审计中心；部署中的日志/轮换由运维负责。

已有平台的接入方法是挂载独立monitor子应用，并注入人的只读登录依赖。设备写入走新接口自己的认证，不扩宽旧ingestion权限，不修改审批或数据库安全函数。由于当前生产源码及部署配置还可能有改动，交付的是经过隔离测试的适配器和代码示例，并未声称现有平台已经接好。

## 技术栈的取舍

Python贯穿ROS适配、汇总、API及Qt，避免为首版增加Rust/Electron或独立RPC语言。它适合当前观察数据量，但并未承诺硬实时，也没有在控制线程中执行Python监控。CPU和丢样必须测量。

PostgreSQL适合沿用现有后端技术与事务能力；SQLite只承担本机待传队列和离线演示。暂不增加Kafka、MQTT、Redis、时序库或Kubernetes。如果实测历史查询/存储量不满足，再针对瓶颈评估分区或压缩，而非预先建设完整数据平台。

桌面首次交付为Python包和启动入口，没有宣称免安装的AppImage/deb或Windows/macOS兼容。ROS运行时须匹配实机Python；桌面与机器人可使用不同环境。Qt版本与显示库需要在目标Ubuntu验证。

## 使用的技能与审查方法

| 技能 | 用途 | 为什么用 |
|---|---|---|
| karpathy-guidelines | 审查假设、缩小范围、定义可验证结果 | 防止把监控需求扩大为复杂测试/Agent平台 |
| fastapi | 路由、依赖、流式读取、WebSocket和生命周期 | 让采集与中央API行为清楚，限制批次大小 |
| api-design | 读写分离、状态码、幂等、查询边界 | 防止补传变重复写和无限历史查询 |
| postgres-patterns | 唯一约束、事务、索引、SQL聚合 | 用数据库保证并发行为，减少Python全量读历史 |
| ui-ux-pro-max | 数据密集布局、单位与状态标识 | 让现场人员区分来源、过期、缺失和上传异常 |

这些技能是开发指导，不是产品运行依赖。额外监督任务持续按里程碑独立审查，报告保存在 `reviews/`。监督窗口不会替代真实机器人验收；本轮结束后的新修改仍需继续提交审查。
