# 整机图的关节温度色阶

网页和原生 Qt 上位机已增加相同的电机部位温度图。颜色从浅粉连续变为深红，温度越高颜色越深；图上显示摄氏度数值，超过人工配置限值时增加红色描边和“超温”文字。色阶范围仅控制显示，不是安全阈值。低于限值也可能呈浅红色，应结合数值和超温标记判断。

电机温度和 MOS 温度分别与各自配置限值比较。只有新鲜、有效的观测参与判断；缺失、过期或未配置限值显示灰色/未知，不填零、不保留旧红色、不宣告恢复。同一部位的多个电机在图上显示已知最高温度，列表保留每个关节和传感器的温度、限值及状态；部分传感器未知时不显示为全部正常，已知的超温不会被缺失值掩盖。图形是机型示意，不是实时姿态。

温度图按当前读数即时更新。中央持久告警仍使用既有 `alert_hold_seconds` 持续确认规则，因此刚超限时图形可以先变红，随后产生告警事件；这是显示和告警确认时间的差别。

## 当前模拟预览

访问 [中央大屏](http://127.0.0.1:18940/)，可查看两台明确标为 simulated 的机器人：一号为 **24 自由度**，二号为 **28 自由度**。温升演示对关节 3、9、15 生成不同相位的 35–95°C 升降温循环，约 75 秒一轮；其他关节保持原有模拟数据。不会向真实机器人发布消息或调用控制服务。

本次演示参数如下，**均不能作为实机限值或物理映射验收依据**：

- 一号机电机／MOS演示限值为60／65°C；二号机为75／80°C，网页换版验收另将二号机 joint.3 电机限值改为76°C。均为模拟参数，判据与中央规则一致为严格大于限值。
- 显示色阶 20–100°C，超出范围使用端点颜色，真实数值仍完整显示。
- 示例的前24个模拟关节被分配到肩、肘、腕、髋、膝、踝的12个示意部位；二号机另外4个关节正常显示温度，但位置标为“部位待确认”。这只是软件演示清单，不能据此认定28自由度实机的关节排序与24自由度相同。

启动已有 Docker PostgreSQL 预览（数据库须已运行）：

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python scripts/run_central_preview.py \
  --runtime runtime/postgres-central --port 18940 --thermal-demo
```

已保存中央配置时，relay自动同步对应机器人的版本，上位机无需再传JSON：

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python -m rp1_monitor desktop \
  --url http://127.0.0.1:18961
```

`18962` 对应28自由度的第二台模拟机器人的 relay。关闭 Qt 窗口只关闭读取连接；后台采集、转发与中央服务由启动器独立管理。不要对同一端口重复启动；Ctrl+C 停止该启动器拥有的模拟进程，保留数据库和缓存。启动器省略 `--thermal-demo` 时保留普通模拟方式，不自动加载演示温度限值。单独启动模拟采集时可用 `agent --source simulated --simulated-dof 24` 或 `28`；此参数不能用于 ROS2 来源。

## 配置入口

管理员可在「机型与温度策略」按机器人维护关节清单、映射、显示色阶及逐电机／MOS限值，保存为数据库版本并记录审计；网页和Qt通过relay使用对应版本，详见 [配置与诊断联动](MONITOR_CONFIGURATION.md)。`joint.N.motor_temperature` 和 `joint.N.mos_temperature` 绑定规范索引N。没有数据库版本时仍支持原有文件方式，见 [模拟策略示例](../examples/thermal-policy.simulated.json)；这时服务文件中的温度规则共用，应核对其适用性。

部位文件见 [模拟部位示例](../examples/motor-map.simulated.json)，按机器人 ID 分开声明 `dof:24` 或 `dof:28`、来源、显示色阶和每个关节的部位。已声明但未收到数据的关节仍保留未知占位；收到清单超出配置时停用部位投影，避免套错机型。支持的部位为 `left/right_shoulder`、`left/right_elbow`、`left/right_wrist`、`left/right_hip`、`left/right_knee`、`left/right_ankle`，对应当前品牌图的固定坐标；这里左右按机器人自身定义。尚未确认位置时可省略 `region`，该关节仍保留温度和超限判断。

ROS2 实机映射还必须填写 `joint_name` 并与观测到的规范索引名称完全一致。在人工核对实际关节名称和部位后，才能把该机器人的 `physical_mapping_verified` 设为 true。未确认、来源不符、名称不符或机器人 ID 不符时，不在图上推断电机位置；温度列表仍可显示收到的数据与超限情况。模拟映射不能套用到 ROS2 来源。机器人侧无需增加绘图、外网连接或中央凭据。

无数据库版本时，中央和独立上位机仍可显式传入原有文件参数：

```text
--policy <经核对的策略.json> --motor-map <经核对的部位映射.json>
```

没有数据库或文件配置时，不默认生成安全温度阈值或实机部位映射。着色和标签属于展示层；原始温度、故障码、时间、缺失值、数据库证据及正式测试/MTBF保持原有含义。点击部位或关节可查询温度双曲线与持久告警时间，并将两项温度指标预填到诊断对话；不会自动发送模型请求。
