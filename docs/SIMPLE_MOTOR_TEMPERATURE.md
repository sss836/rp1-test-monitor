# 最简单的独立电机温度读取

这是一个单文件C++工具，只接收现有CAN反馈，在终端每秒显示一次温度。无需ROS、Python环境或修改运控工程。

当前尚未上传、编译或运行在机器人上。本机已通过编译和合成帧自检，尚未进行真机读取验收。

## 适用范围

- 用于当前已核对的LRO协议；不通用于RP、DM等其他协议。
- 每次选择一条CAN总线上的一个电机ID，不把ID猜成身体部位。
- 读取LRO有效类型1反馈中的电机温度、MOS温度，单位为摄氏度。
- 原系统必须已有反馈；没有反馈时显示`UNKNOWN`。工具不会查询、使能、清故障或初始化电机。

## 第1步：在电脑上传源码

在**上位机终端**执行：

```bash
cd /home/shn/Desktop/rp1-app
scp integrations/robot-health/read_temperature.cpp robo@192.168.137.250:~/read_temperature.cpp
```

含义：只把一个源码文件放入机器人用户家目录，不覆盖原有运控文件。

## 第2步：在机器人编译

先登录：

```bash
ssh robo@192.168.137.250
```

然后在**机器人终端**执行，需要机器人的现有`g++`：

```bash
g++ -std=c++17 -O2 ~/read_temperature.cpp -o ~/rp1-temp
```

含义：生成独立工具`~/rp1-temp`。上位机与机器人架构不同，应在机器人编译，不能直接复制电脑上的可执行文件。

## 第3步：读取一个电机

仍在**机器人终端**执行：

```bash
taskset --cpu-list 1-3,7 nice -n 10 ~/rp1-temp can0 1
```

- `can0`：选择已有的CAN接口，不新建或重新配置接口。
- 最后的`1`：选择这条总线上的电机ID 1。
- `taskset`：只允许新工具使用CPU1、2、3、7，排除CPU0；不调整运控进程。
- `nice -n 10`：降低新工具调度优先级，不是CPU使用率上限。

终端每秒输出一行。`motor`是电机温度，`MOS`是驱动板温度；`age`是基于内核接收时间推算的数据年龄，`rx_unix`是原始内核接收时间，均不代表电机硬件采样时间。超过3秒没有有效反馈时显示`UNKNOWN`；不把零值或旧缓存冒充新数据。`drops`为该socket报告的接收队列累计丢弃数。

按`Ctrl+C`退出，只关闭这个读取工具。它不安装开机自启，也不保存历史曲线。此工具输出尚未接入上位机界面或中央网页。

## 开销和验证范围

程序只保留一台电机的最新状态，接收缓冲区请求值32KiB（Linux可能调整或加倍实际值）。没有不断增长的数据列表，不记录全量CAN日志。总RSS还包含运行库，内核socket缓存不计入进程RSS；当前未测量真机总开销。

**每秒输出一次不等于每秒只接收一帧。** 工具持续读取该ID的现有反馈，避免每秒睡醒后读取队列中的旧帧。因此会有额外的接收处理开销，不能承诺对策略零影响。此版本适合先查看一台电机，不建议同时启动24份；长期全关节监控应另做统一接收和开销评估。

接收按总线和标准CAN ID过滤，支持经典CAN与CAN FD；排除本机发送回环、错误帧、远程帧、扩展帧和不匹配的反馈类型。不修改总线波特率、接口状态或其他socket的设置。内核接收时间缺失、明显过旧或时钟不一致时，不更新有效温度。

本地软件自检无需机器人，也不会打开CAN socket：

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Werror integrations/robot-health/read_temperature.cpp -o /tmp/rp1-temp-local
/tmp/rp1-temp-local --self-test
```

自检覆盖合成反馈解析、负温度、经典CAN/FD、本机TX回环、错误ID/类型/长度、时间过期及未来时间拒绝。这些合成测试不代表已完成实机验证。
