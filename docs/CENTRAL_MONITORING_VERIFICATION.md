## 实现与边界

| 内容 | 当前行为 |
|---|---|
| 关键曲线 | 服务端白名单与不可变策略版本；单位、聚合方式、样本数及缺失值可追溯；网页切换raw/key |
| 容量 | 原始/关键逻辑JSON字节、去重窗口数、UTC日账、1Hz/30天估算；另列数据库物理量 |
| 留存 | 30天候选与归档清单覆盖预览；无删除端点和自动清理任务 |
| 归档 | 最多24小时一次请求、按UTC小时分段、固定原始ID高水位、分批gzip JSONL、完整校验后登记清单 |
| 回填 | 显式追加旧窗口缺少的投影和日账；校验原始哈希和完整身份；不改已有投影或原始证据 |
| 告警 | 进程异常、采集失联/数据过期、网线预览断开、机器人/relay积压及缓存盘不足；温度限值默认未配置 |
| 恢复 | 持续异常确认后打开；只有确认正常才恢复；未知、规则移除和过期不会关闭未恢复事件 |
| 接入 | relay独立状态通道；设备凭据只能写绑定设备；人类只读身份查询；诊断证据包含持久告警 |
| 中央磁盘 | PostgreSQL数据盘和归档盘剩余量明确为unknown，审核后部署时绑定真实挂载盘指标 |

原始与关键数据均保留，归档也只复制。因此白名单投影不代表物理磁盘已经节省，30天配置不代表容量会自动回收。默认采样频率、持续时间和积压阈值均为待实机校准的设计值。

## 使用方法

审核中的 [策略示例](../deploy/central-policy.example.json) 由中央服务启动时加载；页面不写策略或设备凭据。已配置数据库连接环境变量和私有设备/只读配置后，在对应环境执行：

```bash
rp1-monitor server --devices /private/devices.json \
  --viewer-token-file /private/viewer-token.txt \
  --policy deploy/central-policy.example.json --no-initialize
```

`RP1_MONITOR_DATABASE_URL` 通过私有运行环境提供，不把密码写入命令历史或仓库。`--no-initialize` 用于已按审核SQL初始化的数据库；目前不要连接尚未批准创建的PostgreSQL。

旧数据如需关键层，先显式回填；命令不覆盖已有投影：

```bash
rp1-monitor backfill-key-windows --robot-id DEMO-RP1-01 \
  --policy deploy/central-policy.example.json
```

回填完成后可分段复制归档（示例时间须替换为实际审核范围）：

```bash
rp1-monitor archive --robot-id DEMO-RP1-01 \
  --start 2026-10-22T08:00:00Z --end 2026-10-22T09:00:00Z \
  --directory runtime/archives
```

以下查询使用原有人的只读认证，不使用设备上传凭据：

| 路由 | 内容 |
|---|---|
| GET `/api/v1/monitor-storage/usage` | 容量、策略、日账 |
| GET `/api/v1/monitor-storage/retention-preview` | 到期候选和清单覆盖预览 |
| GET `/api/v1/robot-monitors/{id}/alerts` | 当前规则、未恢复标记及评估新鲜度 |
| GET `/api/v1/robot-monitors/{id}/alert-events?before_id=…&limit=20` | 游标分页事件 |
| GET `/api/v1/robot-monitors/{id}/telemetry?tier=key` | 关键层历史，原有时间/指标参数继续适用 |
