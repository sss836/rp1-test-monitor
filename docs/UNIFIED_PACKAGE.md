# RP1 统一源码交付包

统一包将电脑上位机、机器人采集端、网页和独立温度工具的相关文件集中保存，方便一次复制和交付。

**这是源码交付包，不是已经装好依赖的一键安装器。** 包内各部分仍分别在机器人或电脑上运行；仅合并文件不会自动把独立温度工具接入上位机和网页。当前温度工具只经过本地合成测试，未在机器人部署或验收。

## 文件在哪里

| 包内位置 | 内容 | 运行位置 |
| --- | --- | --- |
| `src/rp1_monitor/` | 共用Python源码，含采集端、relay、Qt上位机和中央服务 | 按角色分别运行 |
| `src/rp1_monitor/web/` | 中文网页、三维模型和本地前端依赖 | 由中央服务提供 |
| `integrations/robot-health/read_temperature.cpp` | 单个LRO电机的独立被动温度读取工具 | 机器人 |
| `deploy/` | 配置、启动脚本、服务及PostgreSQL部署模板 | 模板，不会自动执行 |
| `pyproject.toml` | Python包定义和各角色依赖声明 | 安装时按角色选择 |
| `docs/SIMPLE_MOTOR_TEMPERATURE.md` | 温度工具的上传、编译和使用说明 | 供人工操作参考 |
| `docs/ROBOT_CHANGES.md` | 当前项目对机器人实施过的操作说明 | 供审阅，不自动执行 |
| `MANIFEST.json` | 每个文件的大小和SHA256，以及验证边界 | 核对文件完整性 |

包中不包含实际账号、API Key、设备凭据、数据库、真实遥测、运行日志、Python虚拟环境或机器人ROS安装。第三方前端资源随附现有许可证文件。

## 在电脑解压

将压缩包放在准备使用的目录，在该目录执行：

```bash
tar -xzf rp1-monitor-combined-20261026.tar.gz
cd rp1-monitor-combined-20261026
```

解压只创建文件，不会启动程序、建立SSH连接、安装服务或修改机器人。

## 已有上位机仍按原入口启动

本次打包没有替换当前电脑上正在使用的程序。当前已安装上位机的手动启动命令仍为：

```bash
cd /home/shn/Desktop/rp1-app
.venv/bin/rp1-monitor desktop --url http://127.0.0.1:18972
```

该地址连接电脑自己的relay。机器人采集端、独立SSH隧道和relay需要分别运行；打开Qt窗口不会替你安装或启动机器人采集程序。

如果要在新位置或新电脑安装，需先准备与对应CPU架构和Python版本匹配的依赖。依赖由`pyproject.toml`中的`desktop`、`agent`、`server`角色声明；包内没有依赖wheel集合，不能声称支持全新机器离线安装。不能把电脑的`.venv`直接复制给ARM64机器人。

`deploy/`内是通用模板，不是当前机器已核验的配置：ROS路径、CPU集合、端口、设备编号和私有凭据位置都应按现场确认。模板不会自动安装，不能直接覆盖现有独立部署。

## 查看电机温度

按`docs/SIMPLE_MOTOR_TEMPERATURE.md`操作。源码已集中在本包内，不必再从另一个源码压缩包寻找。文档中的电脑工程路径是当前实际路径；若使用解压目录，应把电脑端路径换成你自己的解压位置。

工具只接收已有LRO反馈，不发送读取命令，不创建电机控制对象。没有反馈时显示未知。每秒打印一次仍会处理所选电机的高频反馈，实际CPU、内存及对运控时序的影响尚未实测。

此工具目前输出到终端。要让其温度自动出现在现有上位机和网页中，还需要对本项目采集适配与真实关节身份做单独接入；这一功能没有因为打包而完成。

## 当前执行范围

本次只在上位机生成交付文件，没有上传、编译或启动机器人端温度工具，没有重新启动机器人监控、运控或原有服务。此前按用户要求执行过的`rp-server`停止操作另见改动清单；打包动作不会再次操作该服务。

包内不附带当前机器人私有设备档案、中央地址和访问凭据。原有私有配置保留在各自运行环境中，后续配置或迁移时单独处理。
